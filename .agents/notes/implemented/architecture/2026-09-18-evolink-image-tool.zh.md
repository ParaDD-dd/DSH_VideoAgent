# Agent Note: 按需启用 EvoLink 图片生成

Status: implemented

[English](2026-09-18-evolink-image-tool.md) | 中文

## 问题

Agent 需要图片生成工具，并能通过已有插件设置控制提供方的异步任务。提供方密钥必须避免进入工具参数和持久化设置，取消等待不能创建另一个计费任务。

## 决策

[`tool-image-evolink`](../../../../packages/web/tool-image-evolink/README.zh.md)拥有一个 EvoLink 专用工具，不引入没有其他消费者的提供方注册表。`dsh-video-app` bundle 挂载该插件但默认禁用；其他随附 profile 不包含其 Host 配置行。其 `image-evolink` 设置区控制 `image_generate` 的可撤销注册；Host 提供该设置区时，Plugins 配置标签页才会派发对应卡片。只读清单继续描述 Loader 激活状态，该状态与工具启用状态不同。

每次前台调用创建一个任务，默认每 5000 毫秒轮询一次。部署可配置轮询间隔和总时限。取消、关闭、重新配置和卸载会中止本地 I/O；卸载等待操作结束。工具不重试任务创建，因为响应丢失不能证明提供方拒绝了计费请求。提供方响应不能提供错误文案，携带密钥的请求拒绝重定向。

## 考虑过的替代方案

**分离服务、提供方和消费者包。** 当前只有 EvoLink 生成有消费者。可复用注册表会在没有第二个实现或用户时增加接口。

**分别提供创建和查询两个模型工具。** 这会让模型负责轮询时间，并反复向上下文加入轮询消息。单个前台工具可以执行指定间隔，并通过标准工具结果返回最终 URL。

**从清单修改 Loader 激活状态。** 清单是只读的，卸载插件也会移除其设置区。保留设置贡献方可以在模型工具关闭时继续提供开关。

## 后果

工具通过规范的 `{ taskId, urls }` 输出和已有工具日志事件支持原生与程序化工具模式。它不下载图片、不取消上游任务，也不恢复中断的轮询。调用方必须自行保存提供方的临时图片。编辑 `.env` 中的环境变量密钥后需要重启；启用状态修改即时生效。单元和 Loader 测试验证注册、轮询及失败处理；真实提供方冒烟测试需要 `EVOLINK_API_KEY`。
